### 1. cloudflare/security-audit-skill

**🧩 插件技能** ｜ ★ 本周 **+15,072** ｜ 总星 47,515 ｜ 相对热度 **31.7%** ｜ JavaScript ｜ MIT

**它是什么**

一份给 AI 编程助手用的"安全检查清单"。装进 AI 之后，你让它审计代码，它不再是一遍扫过随口点评，而是按固定的多轮流程逐项排查，每条结论都要附带能被机器验证的证据。

**解决什么问题**

直接跟 AI 说"帮我看看有没有安全漏洞"，结果通常是：漏掉大半、爱编不存在的漏洞、说不出具体在哪一行。问题不在于 AI 不懂安全，而在于它没有一套必须走完的流程。这个项目提供的正是这套流程本身。

**为什么本周火**

相对热度 31.7%——意味着它当前总星里有近三分之一是这一周涨出来的，属于典型的爆发式增长。云厂商开始把"AI 安全审计"做成标准件，正好切中"AI 写代码速度快了，人工审不过来"的痛点。

**时间与成熟度**

2026-06-18 创建（129 天前）｜最近提交在 41 天前
→ 判定：**较新项目**。项目不到半年，但本次单周涨幅极其集中，说明刚被某个渠道带起来，还没经过长期使用检验。

**快速上手**

README 提供了一行安装（需先有 Skills CLI）：

```bash
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit
```

想全局安装（所有项目都能用），加 `--global`。

**应用边界**

适合：已有 AI 编程助手、想在上线前加一道自动检查的团队。
不适合：① 它查的是代码层面的常见漏洞（注入、越权这类），业务逻辑漏洞基本查不出；② 结论仍需人工复核，不能当作合规审计报告提交给监管方；③ 最近 41 天没有提交，规则库可能滞后于最新的攻击手法。

**许可与状态**

MIT ｜维护中：最近提交在 41 天前。许可宽松，但更新频率需要你自己盯一下。

### 3. Graphify-Labs/graphify

**🧩 插件技能** ｜ ★ 本周 **+6,903** ｜ 总星 135,564 ｜ 相对热度 **5.1%** ｜ Python ｜ Apache-2.0

**它是什么**

把你整个项目——源代码、文档、数据库建表语句、配置文件、PDF——读一遍，整理成一张"可以提问"的关系图谱。之后 AI 回答"这个函数被谁调用""改这个字段会影响哪些地方"时，看的是全局，而不是眼前打开的几页文件。

**解决什么问题**

AI 编程助手最大的短板是视野窄：它只读你给它的那几个文件，问到跨文件的依赖关系就只能靠猜，猜错了你还得自己回头查。这个项目相当于给它先画一张地图。

**为什么本周火**

相对热度只有 5.1%，不是突发型。它是搭上了"上下文工程"这个正在升温的方向——大家逐渐意识到，给 AI 喂什么，比换哪个模型更影响效果。

**时间与成熟度**

2026-04-03 创建（205 天前）｜最近提交 2 天前
→ 判定：**较新项目，活跃维护中**。

**快速上手**

README 明确说明这只要两条命令，并特别提醒：PyPI 上的包名是 **`graphifyy`（双 y）**，其他 `graphify*` 包跟它无关——这一点值得留意，装错包是常见坑。CLI 命令本身仍是 `graphify`。

```bash
uv tool install graphifyy      # 安装 CLI（或：pipx install graphifyy）
graphify install               # 自动识别你的助手并注册技能
```

Windows 用户需先装 uv：`winget install astral-sh.uv`。

**应用边界**

适合：中大型代码库、需要频繁做跨文件改动的场景。
不适合：① 首次索引大仓库耗时可能很长，小脚本项目完全没必要；② 它要把代码内容读入分析，涉密项目必须自己确认数据是否离开本地；③ 图谱是静态快照，代码天天大改的项目需要频繁重建。

**许可与状态**

Apache-2.0 ｜正在维护：2 天内有提交。许可宽松，商用友好。

### 5. heygen-com/hyperframes

**🎬 音视频生成** ｜ ★ 本周 **+5,612** ｜ 总星 72,474 ｜ 相对热度 **7.7%** ｜ TypeScript ｜ Apache-2.0

**它是什么**

写 HTML，出视频。它把网页技术当成视频的制作方式——你用 HTML/CSS 描述画面，它把这套渲染成 MP4。

**解决什么问题**

传统做视频要么用剪辑软件（改一个细节要重做一遍），要么写复杂的视频代码（学习成本高）。用 HTML 做视频的好处是：画面即代码，可以像改网页一样改视频，也方便让 AI 直接生成和批量生产。

**为什么本周火**

相对热度 7.7%。"AI 生成内容"从文字图片走向视频是大势，而 HTML 恰好是大模型最擅长生成的格式——这两件事碰到一起，就是它的机会。

**时间与成熟度**

2026-03-10 创建（230 天前）｜最近提交 0 天前
→ 判定：**较新项目，活跃维护中**。

**快速上手**

本项目属于音视频生成类，运行方式与常规工具差异较大（涉及浏览器渲染管线），按约定此处不做展开。想了解请直接看仓库首页的说明。

**应用边界**

适合：需要批量、程序化生产视频的场景（数据可视化视频、模板化营销素材、自动化讲解视频）。
不适合：① 需要真人实拍质感、复杂剪辑效果的场景；② 视频渲染通常依赖无头浏览器，资源消耗大，不适合资源受限环境；③ 如果你的视频只需要做一次，用剪辑软件更快，写 HTML 反而是负担。

**许可与状态**

Apache-2.0 ｜正在维护：当天有提交。

### 6. Comfy-Org/ComfyUI

**🛠 可运行工具** ｜ ★ 本周 **+4,790** ｜ 总星 143,068 ｜ 相对热度 **3.3%** ｜ Python ｜ GPL-3.0

**它是什么**

本地跑 AI 生图的图形界面。用"连线搭积木"的方式组合生成流程——一个节点是模型，一个节点是提示词，连起来就出图。是目前最主流的本地 AI 绘图工具。

**解决什么问题**

早期本地跑图像模型全靠命令行和脚本，改一个参数要改代码。ComfyUI 把整个流程变成可视化的流程图，改参数就是改节点，还能把搭好的流程存下来复用、分享。

**为什么本周火**

相对热度 3.3%，14.3 万星的巨大基数——这是**长期霸榜型项目**的日常波动，不是本周新事件驱动。

**时间与成熟度**

2023-01-17 创建（1,378 天前）｜最近提交 0 天前
→ 判定：**非常成熟的老牌项目**。近四年前创建，至今每天更新，是这一领域的基建。

**快速上手**

README 明确推荐新手**直接用桌面版**，这是最省事的路径。命令行方式为：

```bash
pip install comfy-cli
comfy install
```

**应用边界**

适合：本地部署、需要精细控制生成流程、重视数据不出本地的图像生成需求。
不适合：① **GPL-3.0 许可**——它是传染性许可证，如果你把它的代码集成进自己的产品并分发，你的产品也可能被要求开源，商业闭源项目要格外注意；② 未处理 issue 5,350 个，社区支持靠自助；③ 本地推理需要足够显存的显卡，低配机器体验很差；④ 上手曲线偏陡，节点式操作对新手不友好。

**许可与状态**

GPL-3.0 ｜⚠️ **慎用**：未处理 issue 5,350 个。功能极其成熟，但许可证对企业集成有实质约束。
