10 个项目里有 9 个是给 AI 编程助手"加装能力"的 skill / plugin，只有 TradingAgents 一个是独立可运行的应用。更具体地说，其中 4 个（hallmark、impeccable、taste-skill、claude-seo）在解决同一件事：**让 agent 生成的页面别那么像 AI 生成的**——反 slop 已经从一个吐槽词变成了一个细分赛道。另外两个（ECC、superpowers）做的是 agent 工作流编排，Cloudflare 那个把 agent 变成安全审计员。社区注意力基本全在"给现成模型配零件"，没人造模型。

### 1. Nutlope/hallmark

**🧩 插件技能** ｜ ★ 本周 **+12062** ｜ 总星 44714 ｜ 相对热度 **27%** ｜ CSS ｜ MIT

**它是什么**
一个装进 Claude Code / Codex / Cursor / OpenCode 的设计 skill。它从 50 种材质里抽 3 个主题，围绕"访客来这个页面要干什么"搭页面，然后用真实浏览器检查成品有没有那些一眼看出是机器做的痕迹——每个标题上方的小字眉标、字距拉开的全大写标签、标题里单独染色的一个词、满屏空框。

**解决什么问题**
在这之前，让 agent 写前端，出来的是同一张落地页：居中大标题、渐变按钮、三栏图标。你要么自己动手改，要么反复在 prompt 里加"不要紫色渐变"。hallmark 把"什么算 AI 味"写成了一份可执行的检查清单，交给浏览器去跑，而不是靠你肉眼盯。

**为什么本周火**
相对热度 27%，总星 4.4 万，创建于 2026-04-27（187 天前）——不是全新项目，但本周涨了 1.2 万星，是榜上绝对增量最高的。结合榜上另外三个同类项目同时上榜，更像是"反 AI 设计"这个话题整体被点燃，而不是单个项目的孤立爆发。具体触发点仓库未说明。

**时间与成熟度**
2026-04-27 创建（187 天前）｜最近提交 4 天前
→ 判定：**较新项目**
半年出头，但已有 4.4 万星和 72 个未处理 issue，说明用的人不少、维护还没跟上。

**快速上手**
```
npx skills add nutlope/hallmark -g
```
`-g` 装到全局，去掉则只装当前项目。需要 Node 18+。浏览器检查（`sloplint --render`、截图）还要额外 `npm i -g puppeteer-core` 和 Chrome，不装的话静态检查仍可运行。装完在 Claude Code 里用 `/hallmark <prompt>` 调用。

**应用边界**
适合：你已经在用 agent 写前端，且受够了千篇一律的落地页，愿意为"设计感"多花一轮浏览器校验的时间。
不适合：纯后端项目、对页面加载性能极度敏感的场景（多一层浏览器渲染检查），或者你根本不用这几个 agent 客户端——它是 skill，脱离宿主没有意义。

**许可与状态**
MIT ｜正在维护：3 天内有提交

### 2. pbakaus/impeccable

**🧩 插件技能** ｜ ★ 本周 **+12031** ｜ 总星 99194 ｜ 相对热度 **12.1%** ｜ Rust ｜ Apache-2.0

**它是什么**
给 coding agent 的一套"设计词汇表"。你用 `polish`、`bolder` 这类词指挥它调整视觉，用 `critique`、`audit` 让它自查，在代码提交前把 AI slop 拦下来。核心引擎是 Rust 写的独立二进制，Node 只用来跑 `npx`。

**解决什么问题**
和 hallmark 撞在同一个痛点上，但路线不同：hallmark 是"给你一套设计决策 + 浏览器 lint"，impeccable 是"给你一套可调用的设计指令集 + 检测器"。它支持 17 个以上的宿主（Claude Code、Cursor、Codex CLI、Copilot、Devin、Gemini CLI……），覆盖面是榜上同类里最广的。

**为什么本周火**
相对热度只有 12.1%，但总星已近 10 万，创建于 2025-11-16（350 天前）——典型的老项目再次走红。1.2 万的周增量对 10 万存量来说不算异常，更像是被某个渠道重新推到台前。榜上 hallmark 与它同周上榜、增量几乎相同（12062 vs 12031），两者大概率在互相带流量。

**时间与成熟度**
2025-11-16 创建（350 天前）｜最近提交 0 天前
→ 判定：**成熟项目**
快一年，日更级别提交，61 个未处理 issue 对 10 万星来说算健康。

**快速上手**
```
npx impeccable install
```
安装器会自动探测你装了哪些 coding 工具，问你是装当前项目还是全局，并提示是否装设计 hook——建议接受。装完重启工具，然后在 agent 里跑 `/impeccable init`（Codex 上是 `$impeccable init`）。

**应用边界**
适合：团队里多人用不同 agent 客户端，需要一套统一的设计约束；或者你想在 CI 里跑 `npx impeccable detect` 做静态拦截。
不适合：Codex / Grok Build / Hermes Agent 用户要多一步手动批准 hook，嫌麻烦的话体验会打折；另外它装的是 hook，对构建流程有侵入性，安全策略严格的环境要先评估。

**许可与状态**
Apache-2.0 ｜正在维护：0 天内有提交

### 3. cloudflare/security-audit-skill

**🧩 插件技能** ｜ ★ 本周 **+11908** ｜ 总星 56235 ｜ 相对热度 **21.2%** ｜ JavaScript ｜ MIT

**它是什么**
把 coding agent 改造成安全审计员。它调度多个隔离的 agent 分阶段干活：侦察、按覆盖度找漏洞、验证候选、结构化输出、独立复核每条记录，最后出一份不绑定具体目标的报告。README 说这是 Cloudflare 内部漏洞挖掘流水线的种子版本。

**解决什么问题**
让 LLM 找漏洞，最大的问题是它会一本正经地报告不存在的漏洞。这个 skill 的关键设计是"独立验证"——找到的每一条都要经过另一轮复核才写进报告，输出是机器可读的。这比"让 GPT 看看这段代码有没有问题"要工程化得多。

**为什么本周火**
相对热度 21.2%，创建 136 天，5.6 万星。Cloudflare 官方出品 + 有配套博客文章讲背后的 harness 系统，是本周榜上少数有"大厂工程实践背书"的项目。但要注意它最近一次提交是 9 月 14 日，已经 48 天没动。

**时间与成熟度**
2026-06-18 创建（136 天前）｜最近提交 48 天前
→ 判定：**较新项目**
四个多月，但提交已经停了近七周，110 个未处理 issue 堆着。

**快速上手**
```
npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit
```
加 `--global` 则装到用户级。用 `npx skills --help` 看 agent 选择和非交互参数。

**应用边界**
适合：你想给自己的代码库做一轮系统性的安全排查，且能接受"agent 报出来的东西仍需人工确认"。
不适合：把它当成自动化渗透测试工具直接对着生产环境跑；也不适合期待持续更新的人——48 天没提交、110 个 issue 未处理，遇到问题大概率没人接。

**许可与状态**
MIT ｜维护中：最近提交在 48 天前

### 4. YuJunZhiXue/dsh-purge

**🧩 插件技能** ｜ ★ 本周 **+6641** ｜ 总星 15307 ｜ 相对热度 **43.4%** ｜ JavaScript ｜ Apache-2.0

**它是什么**
DeepSeek Harness 的一个插件，做的是"破甲"——用可替换的提示词绕过模型的安全限制，不同模型配不同提示词，默认提示词面向国产模型。README 里还提到，公开版本现在只允许连接本地实验网段（loopback 和 RFC1918），域名解析结果必须是私有地址或回环地址，否则拦截。

**解决什么问题**
按仓库自述，它解决的是"想让模型做某些被默认拒绝的事"的需求。这类项目长期存在，但通常散落在各种 prompt 合集里，这个把它做成了可安装的插件形态。

**为什么本周火**
相对热度 43.4%，是榜上最高的——总星才 1.5 万，一周涨 6641，接近存量的一半。创建于 2026-08-19（74 天前），属于新项目快速起量。README 开头提到"有人把开源成果拿去卖，之后作者被叫去谈话"，这类叙述本身容易引发传播。具体传播路径仓库未说明。

**时间与成熟度**
2026-08-19 创建（74 天前）｜最近提交 0 天前
→ 判定：**新项目首秀**
两个半月，日更级别提交，但只有 6 个未处理 issue——要么用户少，要么问题都被快速处理了。

**快速上手**
README 明确说了**不要用插件市场**：一键安装会报 `already queued: dsh-purge` 且不执行任何命令；名字也不在 npm registry 上，不要 `pnpm add dsh-purge`。手动路径：
```
git clone https://github.com/YuJunZhiXue/dsh-purge.git "$DSH_HOME/plugins/dsh-purge"
cd "$DSH_HOME/profiles/web"   # 或 profiles/desktop
pnpm install
```

**应用边界**
适合：在隔离的本地实验环境里研究模型行为边界的人。
不适合：任何生产或联网环境——README 自己就把公开版本限制在本地网段了；也不适合不想承担合规风险的个人和团队。这类工具的使用后果由使用者自负，仓库的 Apache-2.0 许可不构成任何使用授权背书。

### 6. JetBrains/thinkrail

**🧩 插件技能** ｜ ★ 本周 **+5738** ｜ 总星 6943 ｜ 相对热度 **82.6%** ｜ TypeScript ｜ Apache-2.0

**它是什么**
JetBrains 出的 agentic IDE。它在 `pi` 这个 coding agent 外面套了一层完整界面，把工作隔离到独立 workspace，用"living specs"给 agent 提供持久的项目知识，技能可复用。README 说下一步要加完整扩展支持，让 ThinkRail 能自己造自己需要的工具。

**解决什么问题**
现在用 agent 写代码，基本是在终端里对话，上下文靠你自己维护。ThinkRail 的思路是把 IDE 那套"项目结构 + 持久状态"重新做一遍，只不过这次是给 agent 用的。隔离 workspace 也解决了"agent 改坏了不好回滚"的问题。

**为什么本周火**
相对热度 82.6%，全榜最高——总星才 6943，一周涨 5738，等于一周涨了近 5 倍存量。创建于 2026-07-08（116 天前），JetBrains 官方出品。这是典型的"新项目首次进入大众视野"，但 323 个未处理 issue 说明涌入的用户量已经超出维护节奏。

**时间与成熟度**
2026-07-08 创建（116 天前）｜最近提交 0 天前
→ 判定：**新项目首秀**
不到四个月，日更提交，但 issue 积压严重。

**快速上手**
macOS / Linux（Windows 下 Git Bash 也行）：
```
curl -fsSL https://raw.githubusercontent.com/JetBrains/thinkrail/main/install.sh | bash
```
装完直接 `thinkrail ~/code/my-repo` 打开项目。需要 PATH 上有 `git`，以及一个模型 provider——可以用 JetBrains AI 登录，也可以自带凭证。桌面版另有各平台安装包，Linux 桌面版要求 glibc 2.38+ 和 GTK 3 等依赖，Ubuntu 24.04 起步。

**应用边界**
适合：想要一个专门为 agent 设计的 IDE、且已经在 JetBrains 生态里的人；愿意尝鲜 nightly 通道的也可以。
不适合：Linux 老发行版用户（glibc 2.38+ 是硬门槛）；生产环境主力开发工具暂时别换——323 个未处理 issue，功能还在快速变动。

**许可与状态**

### 7. obra/superpowers

**🧩 插件技能** ｜ ★ 本周 **+5636** ｜ 总星 310559 ｜ 相对热度 **1.8%** ｜ Shell ｜ MIT

**它是什么**
一套给 coding agent 的完整软件开发方法论，建立在若干可组合的 skill 之上，外加一层初始指令确保 agent 真的会用这些 skill。README 把它描述成"能跑通的方法论"，而不只是工具集合。

**解决什么问题**
agent 写代码的通病是：不先想清楚就动手、不写测试、不回顾。superpowers 把这些工程习惯固化成 skill 序列，让 agent 按流程走，而不是每次靠你在 prompt 里重新叮嘱一遍。

**为什么本周火**
相对热度 1.8%，全榜最低——31 万星的项目一周涨 5636，属于日常水位。创建于 2025-10-09（388 天前），是榜上第二老的项目。它能持续出现在榜单上，靠的是覆盖面：几乎每个主流 harness 都有对应的安装方式。

**时间与成熟度**
2025-10-09 创建（388 天前）｜最近提交 2 天前
→ 判定：**成熟项目**
一年出头，持续维护。377 个未处理 issue 是榜上最多的，但对应 31 万星的体量，比例不算离谱。

**快速上手**
安装方式按 harness 分，用多个就分别装。Claude Code 走官方市场：
```
/plugin install superpowers@claude-plugins-official
```
Cursor 在 agent 对话里：
```
/add-plugin superpowers
```
Gemini CLI：
```
gemini extensions install https://github.com/obra/superpowers
```
其余（Codex、Devin、Factory Droid、Copilot CLI 等）各有命令，见 README 对应小节。

**应用边界**
适合：想让 agent 遵循固定工程流程的团队，尤其是需要"先设计再写码"纪律的项目。
不适合：只想让 agent 快速改几行代码的场景——完整方法论的开销比收益大；另外它按 harness 分别安装，多客户端用户要重复配置。

**许可与状态**
MIT ｜正在维护：2 天内有提交

### 8. TauricResearch/TradingAgents

**🛠️ 可运行工具** ｜ ★ 本周 **+5483** ｜ 总星 119465 ｜ 相对热度 **4.6%** ｜ Python ｜ Apache-2.0

**它是什么**
一个多 agent 的 LLM 金融交易框架。多个 agent 分工做研究、决策、复盘，跑在真实市场数据上。最新版本 v0.7.1 的更新点包括：决策只按最终收盘价计分、跨长假期结算、修复了模型可能读到运行日期之后才发布的财报的问题。

**解决什么问题**
用 LLM 做交易决策，回测最容易自欺欺人——用当天收盘价做决策又用当天收盘价算收益，或者不小心让模型看到了未来信息。这个项目在 v0.7.x 里专门修的就是这类"前视偏差"，说明作者知道坑在哪。

**为什么本周火**
相对热度 4.6%，创建于 2024-12-28（673 天前），是榜上最老的项目。近 12 万星、一周涨 5483，属于长期稳定曝光。10 月连续发了 v0.7.0 和 v0.7.1 两个版本，可能是本周关注度的小幅回升原因。

**时间与成熟度**
2024-12-28 创建（673 天前）｜最近提交 5 天前
→ 判定：**成熟项目**
快两年，版本迭代规律，105 个未处理 issue。

**快速上手**
```
git clone https://github.com/TauricResearch/TradingAgents.git
cd TradingAgents
pip install .
```
需要 Python 3.11+。装完把 `.env.example` 复制成 `.env` 填 API key。想用 Docker 的话：
```
cp .env.example .env  # 填 API key
docker compose run --rm tradingagents
```
本地模型走 Ollama profile：`docker compose --profile ollama run --rm tradingagents-ollama`。

**应用边界**
适合：研究多 agent 协作在金融决策上的可行性、做策略回测实验的人。
不适合：拿它直接管真钱——README 没有给出任何收益保证，而且它需要你自备 LLM API key，每次运行都有实打实的调用成本；也不适合没有金融数据源的人，FRED、Alpha Vantage 等 key 要单独申请。

**许可与状态**
Apache-2.0 ｜正在维护：5 天内有提交
