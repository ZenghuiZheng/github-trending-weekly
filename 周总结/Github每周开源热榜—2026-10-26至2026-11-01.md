### 1. Nutlope/hallmark

**🧩 插件技能** ｜ ★ 本周 **+12062** ｜ 总星 44714 ｜ 相对热度 **27%** ｜ CSS ｜ MIT

**它是什么**
给 Claude Code、Cursor、Codex 这类编程助手装一套"设计规矩"，让它生成的页面别一眼看出是 AI 做的。装好后 agent 建页面时会从 50 套材质里抽 3 个主题，按访客来干什么来组织版面，最后在真实浏览器里跑一遍检查。

**解决什么问题**
AI 生成的落地页有固定套路：每个标题上面挂一行小字、全大写带字距的标签、标题里挑一个词染成彩色、整页空框。这些"机器味"读者说不清但一眼能认出。hallmark 把这些特征写成可检测的规则，在交付前拦下来。

**为什么本周火**
相对热度 27%，是榜上第二高。项目 4 月底创建，本周涨星 12062 却只占总星 27%，说明是**一次集中爆发**而非长期爬坡——大概率是某个版本或某次曝光带来的。具体触发点数据里看不出来。

**时间与成熟度**
2026-04-27 创建（187 天前）｜最近提交 4 天前
→ 判定：**较新项目**
半年历史、仍在活跃提交，但 72 个未处理 issue 说明用户量已经压过了维护节奏。

**快速上手**
```bash
npx skills add nutlope/hallmark -g
```
`-g` 装到全局，去掉就只装当前项目。需要 Node 18+。浏览器检查（`sloplint --render`、截图）还要额外 `npm i -g puppeteer-core` 和 Chrome；不装这两个，静态检查照样能跑。

**应用边界**
适合：已经在用 Claude Code / Codex / Cursor / OpenCode，且对产出页面的观感有要求的人。
不适合：不写前端页面、或者做的是后台管理界面这类"能用就行"的场景——这套规矩的价值全在面向用户的展示页上。另外它只覆盖设计层面，不解决功能正确性。

**许可与状态**
MIT ｜正在维护：3 天内有提交

### 2. pbakaus/impeccable

**🧩 插件技能** ｜ ★ 本周 **+12031** ｜ 总星 99194 ｜ 相对热度 **12.1%** ｜ Rust ｜ Apache-2.0

**它是什么**
给编程 agent 一套"设计词汇表"：`polish` 和 `bolder` 用来指挥它调整，`critique` 和 `audit` 用来审查，交付前用 `detect` 扫一遍 AI 味。和榜上第 1 名撞了同一个赛道，但走的是"给 agent 一套可调用的命令"而不是"给 agent 一套硬性规则"。

**解决什么问题**
agent 听不懂"这里再精致一点"这种话。impeccable 把模糊的设计诉求拆成几个具体动词，让 agent 有明确的执行目标；同时提供一个独立的检测器，可以脱离 agent 单独扫目录或扫线上页面。

**为什么本周火**
相对热度 12.1%，不算新项目爆发——项目去年 11 月就建了，总星已近 10 万。本周涨星和 hallmark 几乎持平（12031 vs 12062），两个同赛道项目同时上榜，更像是**这个品类整体被讨论**，而不是单个项目的孤立事件。

**时间与成熟度**
2025-11-16 创建（350 天前）｜最近提交 0 天前
→ 判定：**成熟项目**
快满一年、总星近 10 万、当天还有提交，属于稳定迭代期。

**快速上手**
```bash
npx impeccable install
```
安装器会自己探测你装了哪些编程工具，问你是装当前项目还是全局，并提示装 design hook——**建议接受 hook**，装完重载工具。之后在 agent 里跑 `/impeccable init`（Codex 上是 `$impeccable init`）。

**应用边界**
适合：多工具混用的人（README 列了 Claude Code、Cursor、Codex CLI、Copilot、Devin、Gemini CLI 等十几个宿主）。
不适合：Codex、Grok Build、Hermes Agent 三个宿主装完还得多一步手动批准 hook，如果你不想碰 hook 机制，只用 `detect` 做静态扫描也行，但那就用不上它的核心能力了。

**许可与状态**
Apache-2.0 ｜正在维护：0 天内有提交

### 3. cloudflare/security-audit-skill

**🧩 插件技能** ｜ ★ 本周 **+11908** ｜ 总星 56235 ｜ 相对热度 **21.2%** ｜ JavaScript ｜ MIT

**它是什么**
Cloudflare 放出来的一个 agent skill，把编程助手变成安全审计员：拆成侦察、按覆盖面找漏洞、候选验证、结构化输出、独立复核记录、出报告几个阶段，每个阶段由隔离的 agent 跑。

**解决什么问题**
让 agent 做安全审计，最大的问题是它会"自信地编"。这个 skill 的设计重点在**独立验证**——发现的问题要经过另一条路径复核，输出是机器可读的，不是一段散文。README 说它是 Cloudflare 内部漏洞发现流水线的种子版本。

**为什么本周火**
相对热度 21.2%，偏高。项目 6 月创建，本周涨星 11908 占总星 21.2%，属于中等强度的集中关注。考虑到出品方是 Cloudflare 且带官方博客背书，更像是**品牌 + 内容**共同推动，而非纯自然增长。

**时间与成熟度**
2026-06-18 创建（136 天前）｜最近提交 **48 天前**
→ 判定：**较新项目，但已进入静默期**
注意：这是榜上唯一一个最近提交超过一个月的项目，110 个未处理 issue 堆着。

**快速上手**
```bash
npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit
```
加 `--global` 装到用户级。其余 agent 选择、非交互参数用 `npx skills --help` 查。

**应用边界**
适合：想给自有代码库做一轮系统性排查、且能接受"agent 出候选、人来定论"这个流程的团队。
不适合：想拿它当自动化扫描器接进 CI 的人——它是 skill 不是 scanner，需要 agent 宿主；另外 48 天没提交、110 个 issue 未处理，指望它跟进最新漏洞类型不现实。

**许可与状态**
MIT ｜维护中：最近提交在 48 天前

**解决什么问题**
README 开头讲的是作者的开源成果被人拿去卖、之后被约谈，因此把公开版限制在本地网络。所以它现在解决的问题更接近"在隔离环境里做红队测试"，而不是原初的通用用途。

**为什么本周火**

**时间与成熟度**
2026-08-19 创建（74 天前）｜最近提交 0 天前
→ 判定：**新项目首秀**
两个多月、当天有提交、issue 只有 6 个（相对总星而言异常低）。

**快速上手**

```bash
cd "$DSH_HOME/profiles/web"   # 或 profiles/desktop

```

**应用边界**

不适合：任何需要访问公网的场景——公开版会直接拦截。另外它的定位本身涉及绕过模型限制，在企业环境、有合规要求的项目里基本不可用；README 也提到二开需要看署名要求。

agent 做页面时没有视觉参考，只能套模板。taste-skill 给它真实照片（来自开放档案，skill 里带署名）和一个明确的艺术方向，产出就不再是平均水平的落地页。
